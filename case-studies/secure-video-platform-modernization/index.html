Secure Multi-Worker Recording Platform Modernization

I modernized a self-hosted conferencing and recording architecture with strict authentication, multidomain operations, reversible cutover and a validated multi-worker export path.

5

parallel workers validated

Exports succeeded · reruns idempotent

Context

An international online platform depended on self-hosted real-time collaboration and recording services. I was the primary implementer of the modernization layer and an operator and major contributor within the wider system; the open-source components and employer product were not my work alone.

Problem

The platform needed stronger access control, reliable multidomain operation, automated certificate handling and a recording path that could scale beyond a single worker without introducing duplicate processing or an irreversible cutover.

Constraints

  • Production changes crossed edge routing, container networking, authentication and recording workflows.
  • Access failures had to be tested as deliberately as successful sessions.
  • Cutover needed explicit apply, validation and rollback paths.
  • Secrets, domains, addresses, routes, recordings and proprietary application integrations could not be exposed.

Responsibilities

I implemented strict JWT controls and negative tests, multidomain DNS and certificate automation, host reverse-proxy cutover, container service rebinding, apply and rollback automation, validation procedures, and recording and export checks. I did not author the third-party collaboration stack or the employer's wider application.

Technical approach

The architecture separates an edge gateway, authenticated conferencing services, the Prosody/Jicofo coordination path, JVB media handling, a bounded Jibri worker pool and a host-side export destination. DNS-based certificate automation supports multiple public names. Host-level Nginx terminates external traffic and WebSocket paths while container services bind to restricted interfaces. Change scripts pair apply actions with rollback actions rather than treating reversal as an afterthought.

Validation strategy

Authentication validation covered accepted tokens and rejected missing, malformed or unauthorized cases. Operational validation progressed from individual components to parallel recording. Five simultaneous jobs were assigned to five distinct workers; expected artifacts were produced, exports succeeded and rerunning the export process remained idempotent.

Outcome

The modernization established a secure, reversible multi-worker recording architecture. Its current tested baseline is five parallel recording workers with successful exports and safe idempotent reruns. Larger figures found in planning material remain capacity objectives rather than achieved results and stay outside the published outcome.

Reliability and rollback considerations

Cutover documentation paired prerequisites, apply steps, health checks, negative tests and rollback procedures. Service rebinding and reverse-proxy changes were treated as reversible production changes, with a known validated baseline retained until further capacity testing.

Security considerations

The release explains authentication and boundary hardening at a control-objective level only. It excludes token material, real domains, internal addresses, routes, topology, customer rooms, recordings, credentials and code that would expose the employer environment.

Lessons learned

Complex platform changes become safer when security failure paths, rollback and idempotency are first-class acceptance criteria. Capacity should stop at the level actually tested.

Skills demonstrated

Linux and Nginx operations, Docker networking, JWT authentication, DNS and certificate automation, production cutover, rollback design, negative testing, parallel workload validation, export reliability and operational documentation.

Generic architecture description

External clients reach an edge gateway that terminates certificates and forwards authorized traffic to an authenticated collaboration service. A coordination layer allocates recording work across a bounded worker pool. Completed artifacts pass through a separately controlled export path. Observability and validation span the gateway, service, workers and export boundary; rollback can restore the prior routing and binding state.
