Production engineering case study

Operating an 80M+ Monthly-Request Platform Across 12 Domains

I operated and evolved the shared production system behind more than 80 million monthly HTTP requests across 12 domains, connecting edge, application delivery, data, security, observability, communications, recovery and business decisions.

Validated result

80M+

HTTP requests per month

12-domain international production estate

Context

Apprentus operated an international marketplace through 12 localized production domains sharing a Rails application and coordinated edge, runtime and data systems. More than 80 million HTTP requests moved through that estate each month, alongside continuous crawler activity, hostile automation, background work and real-time communications.

Problem

The platform could not be operated as a collection of independent technologies. A capacity change in Passenger could move pressure into PostgreSQL. An aggressive edge rule could block customers or legitimate crawlers. Certificate work could affect the application runtime. A provider decision could change cost, recovery and operational complexity at the same time.

Architecture

The public architecture shows the control path without exposing private topology: traffic enters through managed DNS, TLS and edge controls; Nginx and Passenger deliver the Rails application; PostgreSQL and Redis provide state and cache; observability connects customer, host, data, domain and security signals; permanent controls manage threats, crawler trust, certificates, recovery and incidents.

Responsibilities

I became the infrastructure owner and final technical escalation across Cloudflare, DNS, TLS, Nginx, Passenger, Rails operations, PostgreSQL, Redis, Linux hosts, observability, security automation, backup and recovery, communications infrastructure and provider coordination.

Technical approach

I treated the platform as an interconnected system. Before changing capacity, I correlated queues, process counts, memory, connections, cache behavior and background work. Before edge or security changes, I checked legitimate users, administrators, integrations and verified crawlers. Before widening a rollout, I validated dependencies, representative customer paths, alerts and rollback.

Outcome

The estate evolved from undocumented infrastructure into a coordinated production operating model. That model supported 80M+ monthly requests across 12 domains while enabling permanent security automation, measurable PostgreSQL improvement, controlled Cloudflare migration, crawler trust, observability-led recovery and 100 validated recording workers.

Lessons learned

Platform ownership is the responsibility to understand where risk moves. More processes, stricter rules or a more sophisticated provider are not automatically improvements; the right change is the one that strengthens the complete system and remains operable.
